# 成绩分析系统

这是一个面向个人 Windows 电脑使用的成绩分析系统。系统保留 Vue 3 + Element Plus + ECharts 界面，后端使用 Spring Boot，业务数据使用本地 SQLite。当前 `1.1 beta` Windows 便携版使用 Tauri 桌面窗口显示界面，随包附带本地 Java 运行环境。

> `1.1 beta` 是第一代便携试用包，不是安装程序。2026-10-09 已将导出/下载、路由白屏和本地服务启动探测修复打入 EXE 与便携 ZIP，用户在独立电脑排除旧后端占用后已成功启动。综合素质最终等级“两步计算”是此后的本地源码修改，**尚未重新打入现有 ZIP**；本轮没有推送 GitHub。

## 目录

- `frontend/`：Vue 3 前端。
- `backend/`：Spring Boot 本地后端、SQLite 初始化和业务接口。

- `启动本地前端.bat`：Windows 前端开发服务快捷启动。

## 当前功能

- 固定单用户菜单和免登录，启动后直接进入年级管理。
- 年级、班级、学生、教师、学科、考试和成绩管理。
- SQLite 本地数据库、本地文件存储、备份、恢复和最近 30 份备份管理。
- 成绩 Excel 上传、校验、差异预览、确认提交、批次记录和撤销第一版；另有“独立成绩分析”数据集导入，不改基础学生/班级档案。
- 正常 0 分、缺考、未选科三种成绩状态；免考、缓考、作弊、违纪暂不加入。
- 考试管理按学段（初中/高中）→年级→班级筛选，并提供年度/学期筛选；学期选项由 SQLite 初始化保证可用。考试类型、编码、对象摘要和状态不在管理界面展示，编码与类型仅保留为内部兼容字段；列表人数显示为“考试人数”。
- 考试级科目、满分和计入总分配置第一版，已接入总分、排名、分析和报告；考试对象设置仍保留，方便定义本场考试的年级/班级范围。
- 年级/班级/学生分析、教师任教班级对比、历次考试对比、进退步、临界生和偏科分析。
- 学生个人报告按指定模板动态生成：支持单人 Excel、四页 A4 PDF，以及班级批量独立 Excel/PDF 的 ZIP；Excel 只保留综合分析、趋势变化、学科诊断、家长沟通四个工作表。报告可动态扩展初高中科目，缺考/未选科/缺失不会伪装为 0 分，正常 0 分仍参与统计。
- 学科独立分析及通用 Excel/PDF 报告第一版。
- 高中 3+1+2 选科组合历史和赋分配置框架；具体赋分算法按要求暂停。
- 初中综合素质评价支持单独上传工作簿，无需先建基础学生和班级；六学期、五维度、最后学期名单范围、缺失说明、教师复核、锁定和导出第一版。当前源码先计算已录分值，再由使用者确认含 N/A 维度的最终累计分；全部确认后五个维度各自按最终分值排名、各自按最终名单人数与 A/B/C 比例生成等级。旧版 ZIP 尚未包含这一调整。
- 学生学习状态和跟进记录第一版。
- 学生列表仅显示学号、姓名、入学年份和备注，支持年级→班级筛选；表单不显示性别、出生日期和状态，头像、年龄和班级列表不展示。底层班级归属关系仍保留。
- 教师列表仅保留姓名、所带班级和任教学科；教师工号、性别、电话、状态和行操作列已从管理页移除，点击姓名可编辑，批量删除仍在列表上方。教师表单不显示工号、性别、电话、状态。
- 班级页面不再展示班级类型/名称、教学和学生数量/列表、状态；班级名称由系统按编号内部生成，页面保留年级、班级编号、班主任、排序及必要操作。
- 年级编号/名称可直接录入；新增班级时可直接输入已有年份（如 `2026`）与班级编号（如 `01`），系统按年份匹配已有年级。年份尚未建档时，需先在年级管理中创建。
- 页面右上角的全屏/布局大小/语言/主题/本地用户设置入口已移除；Excel 导入仅通过文件选择按钮，不支持拖拽上传。

## Windows 1.1 beta 便携包

第一代试用包输出到 `outputs/成绩分析系统_1.1(beta)_Windows_x64.zip`（2026-10-09 生成，约 107.7 MB）。将 ZIP 完整解压后，双击 `成绩分析系统.exe`，系统会在独立桌面窗口中打开，不会启动外部浏览器。关闭窗口会停止本次启动的本地服务。压缩包内含 Tauri 窗口程序、本地后端和 Java 运行环境，不需要预装 Node.js、Java 或 Maven。请勿单独复制 EXE。Windows 10/11 通常已安装 WebView2 Runtime；如提示缺少，请安装 Microsoft Edge WebView2 Evergreen Runtime。

ZIP 包含 EXE、backend.jar、Java runtime 和使用说明，不包含 SQLite 数据库或成绩工作簿。已包含统一导出保存逻辑。新 EXE 在开发机上使用隔离数据目录冷启动成功，内置服务就绪后，6 个路由、81 个请求通过冒烟检查（0 API 错误、0 浏览器异常）；另一台 Windows 电脑尚未用新 ZIP 离线验收。发行文件仅保存在本机 `outputs/`，本轮未推送 GitHub。

如果窗口出现“127.0.0.1 拒绝连接”或启动错误，请先确认整个 ZIP 已解压、`成绩分析系统.exe` 与 `backend.jar` 和 `runtime` 在同一目录，再关闭旧版程序后重试。启动记录位于 `%LOCALAPPDATA%\成绩分析系统\logs\launcher.log`；另一台电脑仍失败时，请提供该电脑的启动记录和错误截图。开发机上直接编译的临时测试窗口可能指向未启动的前端开发服务，不等同于本节的完整便携包。

### 导出与下载

- 桌面窗口版点击导出后会弹出“保存导出文件”对话框；选择保存位置后，系统会显示完整文件路径和“导出完成”提示。
- 浏览器调试版会按浏览器默认下载设置保存；页面提示可按 `Ctrl+J` 查看文件位置。
- 如果服务返回错误文本而不是 Excel/PDF/ZIP，系统会显示错误，不再把错误响应伪装成下载文件。
- 以上修复已包含在 2026-10-09 重新生成的 `1.1 beta` EXE/ZIP 中；启动新 EXE 后可验收原生“另存为”流程。

用户数据保存在 `%LOCALAPPDATA%\成绩分析系统`，与程序解压目录分开。要重新生成包，在本仓库根目录执行：

```powershell
pwsh -NoProfile -File .\scripts\package-windows-beta.ps1 -ReplaceExisting
```

此包用于第一轮试用；使用学校正式成绩表之前，请先用备份功能保护数据，并核对导入预览、计总分口径和学生匹配结果。首次启动会在后台启动本地 API，数据保存在 `%LOCALAPPDATA%\成绩分析系统`。

安装前端依赖：

```powershell
cd frontend
pnpm install --frozen-lockfile --ignore-scripts
cd ..
```

## 启动本地服务

### 1. 启动后端

在项目根目录执行：

```powershell
pwsh -NoProfile -File .\scripts\build-backend.ps1 -MavenArguments @('spring-boot:run')
```

或者进入 `backend/` 后执行：

```powershell
mvn spring-boot:run
```

后端地址：`http://127.0.0.1:8989`。首次启动会创建：

- `backend/data/school.db`：SQLite 数据库。
- `backend/files/`：本地上传文件。
- `backend/backup/`：备份文件。
- `backend/export/`：导出文件。

数据库结构使用 V1-V7 本地版本记录自动升级。检测到旧库时，程序会先在 `backend/backup/` 生成并校验 `school_pre_migration_*.db`，再按事务执行升级；该备份可在“数据工具→数据备份”中查看和恢复。重复启动不会重复执行已经完成的版本。

桌面封装或便携运行时可设置 `SCORE_ANALYSIS_HOME` 指向可写的数据根目录，数据库、上传文件、备份、导出和日志会统一写入其下的 `data/`、`files/`、`backup/`、`export/`、`logs/`。开发阶段不设置时仍使用当前工作目录；`LOCAL_DB_URL`、`LOCAL_FILES_DIR`、`LOCAL_LOG_DIR` 可分别覆盖单项路径。

### 2. 启动前端

另开一个 PowerShell：

```powershell
cd frontend
pnpm dev
```

打开 `http://127.0.0.1:3000`。也可以双击根目录的 `启动本地前端.bat`。

生产资源预览：

```powershell
cd frontend
pnpm build:prod
pnpm preview
```

预览地址为 `http://127.0.0.1:4173`。不要双击 `frontend/index.html`，浏览器不能直接以 `file://` 正常运行 Vue 应用。

## 使用顺序

1. 进入“基础信息”，维护年级、班级、学生、教师和学科。为年级直接录入编号/名称并选择初中或高中；班级表单直接输入已建档年份与编号（例如 `2026`、`01`）。
2. 在学生资料中建立班级年度关系；在教师资料中维护教师基础信息，并在新增/编辑弹窗按“年级→班级→任教学科”添加任教关系。教师列表会同步显示所带班级和任教学科。
3. 进入“考试管理”创建考试，按学段、年级、班级筛选并配置本场科目、各科满分和是否计入总分。
4. 若使用基础学生档案成绩链路，进入“成绩录入”上传 Excel，先查看校验结果和差异预览，再确认提交。若只想用成绩表临时建独立分析集，进入“独立成绩分析”，上传文件并填写年级、班级标签；不会改动基础学生和班级资料。
5. 对缺考和未选科使用明确状态；正常 0 分必须保留为正常成绩。
6. 使用“学情分析”查看年级、班级、学生、教师和学科分析；在学生分析中选择考试后，可导出单人 Excel/PDF，或按班级批量导出每位学生的独立文件。
7. 初中综合素质评价直接上传信息表即可，不要求预先关联基础年级、班级或学生；最终范围由最后一个学期名单确定。当前源码先计算已有分值，再确认含 N/A 维度的最终累计分；全部确认后五维分别按本维度分值排名并按比例生成 A/B/C，最后由教师复核并锁定。现有 ZIP 仍是旧口径，不能用于验收这一步。
8. 定期在数据工具中执行备份；恢复时选择系统生成的备份文件，恢复完成后重新打开业务页面核对数据。跨电脑只转移脱敏备份，不复制真实数据库到 GitHub。

## 数据和隐私

运行数据、上传文件、备份和导出目录均已加入 `.gitignore`，不会随源码提交。不要把以下内容加入 Git：`backend/data/`、`backend/files/`、`backend/backup/`、`backend/export/`、真实学生 Excel 或真实报告。

删除或迁移数据库前，先从系统执行一次备份并确认备份文件可读。不要把原始 ZIP 的 MySQL SQL 直接导入当前 SQLite 环境，也不要把真实学生数据发送到外部接口或对象存储。

## 常见问题

### 页面空白或提示本地服务请求失败

确认后端终端仍在运行，并检查 `http://127.0.0.1:8989` 端口是否被占用。前端只代理到本机 8989，不需要启动 MySQL、Redis 或 MinIO。

### 端口被占用

关闭占用 `3000`、`4173` 或 `8989` 的旧进程后再启动。项目不会自动改用其他端口，避免前端代理地址不一致。

### 跨电脑没有原来的数据

源码仓库不包含本地数据库，这是刻意的隐私保护。通过系统备份功能导出备份文件，再在另一台电脑恢复；不要直接提交 `school.db`。

### 导入结果和学校表格不一致

先保留原表的脱敏副本，记录工作表名称、表头行、状态文字和分数规则，再在《需求文档逐项核对》中登记，不能直接猜测学校规则。
