## 2. 已完成阶段

### 阶段 B：基础资料和成绩基础链路（第一版已完成）

### 阶段 C：分析和报告（第一版已完成）

- 年级/班级/学生分析、教师诊断、历次考试对比、进退步、临界生、偏科。
- 学科独立分析。
- 学生个人 Excel 和通用 Excel/PDF 报告。

- 个人和批量报告按 `studentId + examId` 组装同一份数据，初中、高中共用链路；缺考、未选科、缺失成绩不参与总分/等级，并在明细中保留状态。
- 报告按考试实际科目数动态扩展模板，不再受示例模板 8 科限制；各场考试独立读取科目、满分和计总分配置，未选科不进入该生适用满分，缺考保留适用满分但不计得分。
- 导出前已将模板公式固化为结果并删除数据源工作表，避免 Excel 重算出现 `#REF!`；批量 ZIP 内每位学生的文件名、姓名和报告内容逐一对应。
- 报告边界回归已完成：无有效计总分成绩显示为 `—/暂无`，与正常 0 分明确区分；旧考试未配置科目时只回退到实际成绩科目；动态增加到第 9 科以后仍保留数据条和色阶；同一学生的文件名、Excel 和 PDF 共用一次数据组装。

### 阶段 D：高中选科和初中综合素质评价（第一版已完成）

- 高中 3+1+2 选科组合历史和赋分配置框架。

- 高中赋分算法按要求暂停。

## 4. 每项开发的验收顺序

1. 先确认学校样表或规则，不凭示例数据推断。
2. 修改前检查现有接口、Mapper、前端 API 类型和数据库迁移。
3. 先完成后端数据口径，再接入页面和导出。
4. 用脱敏或虚拟数据验证新增、修改、删除、重复导入、空白和异常状态。
5. 每次修改运行：
   - `pnpm typecheck`
   - `pnpm build:prod`
   - `node scripts/check-contracts.mjs`
   - `pwsh -NoProfile -File .\scripts\build-backend.ps1`
   - 启动本地服务后运行 `node scripts/smoke-frontend.mjs`
6. 更新本文件、总表和需求核对文档，再决定是否提交 Git。
