## 2. 已完成阶段

### 阶段 A：单机化和外围精简（已完成）

- 固定单用户菜单和免登录。
- 移除首页、登录、权限、JWT、Redis、问卷、错题/题库等无关模块。
- 切换 SQLite、本地文件和备份恢复。
- 删除运行时 MySQL、MinIO、OSS 依赖及历史初始化脚本。

### 阶段 B：基础资料和成绩基础链路（第一版已完成）

- 年级、班级、学生、教师、学科、考试和成绩管理。
- 成绩导入预览、差异确认、批次记录、撤销。
- 正常 0 分、缺考、未选科状态。
- 考试级科目、满分、计入总分配置。

### 阶段 C：分析和报告（第一版已完成）

- 年级/班级/学生分析、教师诊断、历次考试对比、进退步、临界生、偏科。
- 学科独立分析。
- 学生个人 Excel 和通用 Excel/PDF 报告。

### 阶段 D：高中选科和初中综合素质评价（第一版已完成）

- 高中 3+1+2 选科组合历史和赋分配置框架。
- 综合素质评价六学期、五维度、九下名单、缺失确认、教师复核和导出；确认后存在缺失学期的学生五维最终等级为 `N/A`，不参与 A/B/C 比例和排名。
- 高中赋分算法按要求暂停。

## 4. 每项开发的验收顺序

1. 先确认学校样表或规则，不凭示例数据推断。
2. 修改前检查现有接口、Mapper、前端 API 类型和数据库迁移。
3. 先完成后端数据口径，再接入页面和导出。
4. 用脱敏或虚拟数据验证新增、修改、删除、重复导入、空白和异常状态。
5. 每次修改运行：
   - `pnpm typecheck`
   - `pnpm build:prod`
   - `node scripts/check-contracts.mjs`
   - `pwsh -NoProfile -File .\scripts\build-backend.ps1`
   - 启动本地服务后运行 `node scripts/smoke-frontend.mjs`
6. 更新本文件、总表和需求核对文档，再决定是否提交 Git。

## 5. 当前风险与约束

- 没有学校正式成绩表和报告模板时，只能完成通用第一版，不能标记为正式验收。
- 高中赋分政策和群体未确认，禁止自行实现“看似正确”的算法。
- 数据库兼容字段可以暂留，但新增页面不得重新展示已移除的头像、年龄等字段。
- 真实学生数据只允许留在本机 SQLite/备份，不得提交 GitHub 或上传外部服务。
- 最终 EXE 前必须验证备份恢复、路径权限、升级覆盖和异常退出恢复。

## 6. 交接动作

- 单位电脑：克隆 `master`，安装 Node.js/pnpm、Java 17/Maven，按根目录 README 启动。
- 继续开发：先阅读《需求文档逐项核对.md》和本文件，再从最高优先级未完成工作包开始。
- 提交前：检查 `git diff`、运行全部验证命令，不提交 `backend/data`、`files`、`backup`、`export` 和真实样表。
