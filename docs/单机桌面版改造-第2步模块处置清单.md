# 单机桌面版改造：第 2 步模块处置清单

本清单以“保留现有 UI，先精简后端与业务，再迁移 SQLite，最后 Tauri 桌面化”为原则。分类表示目标状态；实际删除按依赖解除顺序执行。

> 当前状态同步（2026-09-24）：本文仍保留目标处置清单，同时在文末增加了逐项实现状态。首页原计划替换为数据仪表盘，但用户随后明确要求移除首页；当前已删除首页路由、菜单和组件，启动后进入“年级管理”。

## 实施依赖顺序

1. 建立正式改造工作副本、Git 基线和可重复依赖锁。
2. 建立固定菜单/路由并保留 Layout 组件，先让 UI 脱离 `sys_menu` 和角色权限。
3. 解除学生、班级和基础资料对外围模块的依赖。
4. 删除问卷、错题、兴趣、院校、演示、权限页面及后端分支。
5. 简化登录并移除 Spring Security/JWT/Redis。
6. 将 OSS 文件调用替换为本地文件抽象，再删除 MinIO/阿里云依赖。
7. 设计 SQLite 目标表和 MySQL 数据迁移程序，再切换数据源与 SQL。
8. 验证基础资料、考试、成绩导入/查询、三类现有分析。
9. 增加学科、个人、进退步、临界生和报告模块。
10. 增加自动备份、立即备份和恢复。
11. 引入 Tauri，先承载 Vue；若保留 Java 过渡后端则内置精简运行时并由 Tauri 管理。
12. 评估并逐步将稳定的 Java 业务迁入 Rust Command，最终形成便携 EXE。

## 下一阶段验收标准

第 3 步“精简菜单和路由”完成时，应同时满足：

- UI 主框架和现有主题不变。
- 只出现目标菜单，所有菜单均可进入有效页面。
- Sidebar、Breadcrumb、TagsView 正常联动。
- 不依赖登录 token、角色或菜单接口即可访问页面。
- 保留页面的 TypeScript 编译通过。
- 尚未删除后端模块，保证改动可回退并便于逐步迁移。
