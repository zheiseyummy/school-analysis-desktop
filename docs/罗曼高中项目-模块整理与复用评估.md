# 罗曼高中项目整理与模块借鉴清单

> 历史评估快照（2026-09-23 初始审查）。本文记录原始源码的静态结构和当时的复用判断；其中“未安装依赖、未运行测试”等描述不适用于后续已完成的过渡工程验证。当前状态请以《单机桌面版改造-阶段进度.md》及《项目需求与完成状态总表.md》为准。

整理日期：2026-09-23。依据：用户提供的项目压缩包、成绩分析系统需求MD及本轮确认、实际Excel样表。

## 1. 结论

项目有真实的学校业务源码，适合选择性借鉴学生历史成绩展示、班级/年级分析表格、图表和基础资料管理。不能直接视为满足需求的离线EXE成品。建议采用“保留可用展示组件、重新设计本地数据与统计规则”的方式；这不是技术栈定稿，也没有开始移植。

本次完成静态源码检查：压缩包结构、依赖清单、根许可证、实体、导入入口、保存逻辑、统计SQL、分析接口和部分前端组件。未安装依赖、运行数据库脚本、启动服务、执行测试或验证打包；运行效果与构建成功率尚未验证。README主要介绍上游后台模板，不能据此认定学校模块能力。

## 2. 项目构成与技术

外层压缩包包含两个独立源码包：

| 部分 | 目录 | 从清单确认的技术 |
|---|---|---|
| 前端 | luoman_highschool_frontend-master | Vue 3、TypeScript、Vite 5、Element Plus、Pinia、ECharts、Axios |
| 后端 | luoman_highschool_backend-master | Java 17、Spring Boot 3.2.2、MyBatis-Plus、MySQL、Redis、Spring Security/JWT |
| Excel | 后端导入及导出 | EasyExcel、Hutool ExcelWriter |
| PDF | 后端视图 | iText 5.2.0、itext-asian 5.2.0 |

版本依据压缩包内package.json/pom.xml，不表示当前最新版或已验证兼容。后端还声明对象存储、任务调度等依赖，不能把“声明了依赖”直接当成所有功能启动必需。

原项目是前后端分离的Web系统。若用于本地离线EXE，需要处理桌面封装、运行时随包交付、本地数据存储、去除登录依赖、清理远程接口/资源配置和离线导出。Web技术本身可以在本机运行，但当前包没有验证上述交付链路。

## 4. 不能照搬的已核实规则

### 4.1 总分并列排名不一致

SysScoreMapper.xml的多个总分排名查询使用DENSE_RANK；单科查询使用RANK。总分会出现1、2、2、3，而需求明确为1、2、2、4。所有排名入口需要统一规则，并先确定参与学生群体。

### 4.2 部分缺考会进入总分求和及排名

总分查询按学生直接sum(score)，没有校验应考科目是否完整。saveScore会过滤空值，但成绩实体没有明确的缺考/未选/待确认状态。这不能满足“已考科目正常统计，部分缺考不参加总分排名”。不能仅靠过滤null实现需求。

### 4.3 优秀线为90%，需求为默认80%

ScoreUtils.scoreDegreeCalc把满分90%以上分为A；aRate以A人数计算优秀率。用户需求为默认80%，且每次考试可修改。因此不能照搬A至E的阈值及界面标签。分数段默认边界仍待定。

### 4.4 满分取自当前课程资料

保存成绩时调用course.getFullScore()，展示统计也从当前课程对象获取满分。用户要求每次考试独立保存满分和统计标准，后续修改不能影响历史。应建立考试科目配置及快照。

### 4.5 重导没有写入前确认链路

ScoreImportListener逐行调用保存服务；saveScore对已有成绩直接更新，空值跳过。用户要求写入前展示差异，空白含义先确认，保留修改记录并可撤销。应先解析和校验到暂存结果，再由用户确认后按批次提交。

### 4.6 历史教师归属可能被当前关系覆盖

SysScore存有教师ID及班级/年级信息，具备部分归属快照思路；但saveScore更新已有成绩时会重新写入当前SysArrange的教师ID。SysArrange本身没有生效时间字段，SysClazzStudent只到年度。须补时间有效区间，并避免重导旧考试时改写历史归属。

### 4.7 历史对比尚非完整进退与偏科分析

学生接口已经返回历次成绩、单科与总分排名；趋势组件绘制分数折线。但这不能等同于已经实现“排名变化”“单科相对总分排名差的变化”，也未见该链路完整处理跨考试总分科目/满分差异及用户确认。

### 4.8 班级整体统计需明确指标含义

getGradeClazzStaticsList直接对该班所有成绩行计算avg(score)，不是先按学生求总分再取平均。若作为班级总分均分会产生口径错误；不同科目满分、参试人数不同时也不能直接用于教学优劣判断。单科统计更适合在明确分母后复用思路。

### 4.9 导出覆盖范围有限

已核实的是班级某次考试表格的Excel/PDF接口；学生分析接口返回数据并不代表具备个人信息单导出。现有PDF使用固定表格、品牌内容和非嵌入中文字体，需验证中文显示、宽表分页、打包后资源加载并按用户模板重做布局。

## 5. 不纳入本项目的内容

- 多人登录、角色、菜单权限、部门权限等后台管理体系。
- 问卷调查、题库、兴趣爱好、高校志向等本次需求之外的业务。
- WebSocket演示、富文本演示及其他后台模板演示页。
- 对象存储、云服务和分布式任务等不应成为本地核心功能的前提。

“教学安排”中的教师—班级—学科关系与需求相关，不应因名称含“安排”就误删；它与排考不是同一功能。

## 6. 许可证与来源记录

前端根LICENSE为MIT，署名为有来开源组织；后端根LICENSE为Apache License 2.0。前端另有上游模板licenses目录。README、package元信息主要指向上游有来框架，尚未独立确认学校定制仓库的具体所有者、提交版本和新增代码来源。

这些是压缩包内文件的核对结果，不是对全部文件和第三方依赖授权范围的完整审查。特别是PDF模块引入独立的iText依赖，不能用项目根许可证代替其依赖条款。实际移植前应核对所选代码来源、依赖许可证、保留声明及修改记录；本次未复制代码进入新产品。

## 7. 后续开发采用顺序

1. 先确定满足本地离线EXE的技术方案与考试/学生/选科历史模型。
2. 实现成绩暂存导入、规则确认、校验和变更预览，使用脱敏或模拟数据。
3. 独立实现统计核心：缺考排除、完整总分资格、1/2/2/4排名、同群体排名差与比较口径。
4. 选择性适配学生历史成绩表、趋势图、班级及年级比较组件。
5. 实现教师教学诊断，以及用户样表对应的进退、偏科汇总和学生个人信息单。
6. 完善四层级Excel/PDF及批量导出、备份恢复和EXE打包。

赋分计算仍按原需求暂缓到群体及规则确定后实现。此次项目整理不改变已确认业务规则，也不将项目自带模块自动扩为需求。
