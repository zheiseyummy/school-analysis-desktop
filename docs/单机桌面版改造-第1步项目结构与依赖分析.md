# 单机桌面版改造：第 1 步项目结构与依赖分析

> 历史分析快照（2026-09-23 初始审查）。其中“应建立 Git”“尚未验证构建”等表述是分析当时的状态，不代表当前工作区状态。当前构建、测试、Git 和同步进度请以《单机桌面版改造-阶段进度.md》《项目需求与完成状态总表.md》《需求文档逐项核对.md》及《成绩分析系统计划与进度.md》为准。

分析日期：2026-09-23  
分析对象：用户提供的成绩分析系统前后端源码包
目标基线：本地离线、单用户、Windows 10/11、尽量保留现有 Vue3 + Element Plus UI，最终由 Tauri 打包为可直接运行的 EXE。

## 1. 本阶段边界

本阶段只分析结构与依赖，没有删除或迁移业务代码。已进行静态源码检查、SQL 结构检查和前端基线构建。后端基线构建在首次下载依赖中，最终结果另行补充。

项目压缩包本身不是一个完整 Git 仓库，前后端各自独立，缺少提交历史；前端也没有随包提供 `pnpm-lock.yaml`。后续正式改造前应建立新的本地 Git 仓库并保存原始基线。

## 2. 总体架构

当前系统是典型的服务器型前后端分离应用：

```text
Vue3 + Element Plus 浏览器界面
          │ HTTP/JWT
Spring Boot 3 Web 服务（内嵌 Tomcat）
          ├── MySQL：全部业务数据
          ├── Redis/Redisson：缓存及验证码等基础能力
          ├── MinIO/阿里云 OSS：文件上传
          ├── Spring Security + JWT：用户认证和权限
          └── WebSocket、Swagger、XXL-Job 等服务器能力
```

现状不能直接生成符合目标的绿色 EXE。第一阶段可以保留 Spring Boot 作为过渡业务层，但最终用户不得安装 JDK、Tomcat、MySQL、Redis、Node.js。若过渡版继续携带 Spring Boot，需要将精简后的 Java 运行时作为应用资源随包交付，并由 Tauri 启停本地进程；第二阶段再评估将 Java 业务逐步迁入 Tauri Rust Command。

## 3. 前端结构

### 3.1 技术组成

- Vue 3、TypeScript、Vite 5。
- Element Plus、Element Plus 图标、ECharts。
- Pinia、Vue Router、Axios。
- UnoCSS、Sass、国际化、动态路由和按钮权限指令。
- SheetJS `xlsx`，另有后端 Excel/PDF 导出能力。

### 3.3 路由与菜单关键依赖

当前业务菜单不是固定写在前端。登录后执行以下链路：

```text
JWT token
  → 获取当前用户 roles/perms
  → GET /api/v1/menus/routes
  → 从 sys_menu + sys_role_menu 生成动态路由
  → import.meta.glob 加载对应 views 页面
  → Sidebar、Breadcrumb、TagsView 共用该路由树
```

因此，精简菜单不能只删除数据库菜单或 Vue 页面。安全顺序应为：先建立新的固定业务路由树，让 Sidebar/Breadcrumb/TagsView 继续消费路由元数据；再移除 token、用户信息和动态权限；最后删除菜单、角色和用户相关后端模块及表。

### 3.4 当前业务页面

当前已有可复用页面：年级、教师、班级、学生、学科、考试、成绩录入、班级分析、年级分析、学生分析和教学安排子页面。

当前未具备完整页面：成绩独立查询、学科分析、进退步分析、临界生分析、简化学生备注、备份恢复、系统设置、个人 Excel/PDF 批量报告。

首页虽已有 `el-card` 和多种 ECharts 组件，但内容是收入、利润、订单等模板演示数据，不是成绩业务首页。

## 5. 数据库结构

## 6. 核心依赖关系

```text
年级
 └── 班级
      ├── 学生班级历史 ── 学生 ── 学生备注/跟进
      └── 教学关系 ── 学科 ── 教师（精简版）

考试
 ├── 考试对象（年级/班级）
 ├── 考试学科配置（新增）
 └── 成绩
      ├── 导入批次与变更日志（新增）
      ├── 班级/年级/学科统计
      ├── 学生排名与趋势
      ├── 进退步分析
      └── 临界生分析
```

删除保护关系：

- 删除年级前必须检查班级、考试和历史成绩。
- 删除班级前必须检查学生归属、教学关系、考试主体和历史成绩。
- 删除学生、学科或考试时应优先采用停用/归档，避免破坏历史报告。
- 错误成绩可以删除，但必须留下变更日志，且删除后重新计算关联统计。

## 7. 当前实现与目标规则的差距

1. 总分排名 SQL 部分使用 `DENSE_RANK()`，产生 1、2、2、3；需求为 1、2、2、4。
2. 成绩实体只有数值，没有缺考、未选、未录入等状态；已有总分 SQL 会直接累加现有科目。
3. 优秀等级 A 当前按 90% 计算，需求默认优秀线为 80%，并允许按考试修改。
4. 学科满分从当前学科资料读取，没有考试级历史快照。
5. Excel 导入依赖固定表头，逐行直接写库，没有导入预览、空白确认、批次撤销和完整变更日志。
6. 成绩重写时会从当前教学关系覆盖教师 ID，可能改变历史归属。
7. 学生历史页面已有成绩和排名，但缺完整进退差值、偏科变化、跨考试口径提醒和个人报告导出。
8. 班级总体统计中存在直接对所有成绩行求平均的查询，不能直接解释为班级总分均分。
9. PDF 只覆盖班级表格，使用旧版 iText 和固定字体/品牌资源；需更换实现并验证许可及中文分页。
10. 前端和配置中存在远程链接、在线文档、生产数据库地址和 OSS 配置，桌面版必须全部移除或禁止访问。

## 8. 基线构建结果

### 前端

- Vite 已成功转换 2821 个模块并生成 `dist`。
- 随后 `vue-tsc --noEmit` 失败：源码包缺少锁文件，安装到 TypeScript 5.9.3，而 `vue-tsc 1.8.27` 与其不兼容。
- 构建还报告 `.env` 中不受支持的 `NODE_ENV=production` 写法、Sass 旧 API 警告以及多项过期依赖。
- 后续必须锁定兼容版本并提交 `pnpm-lock.yaml`，不能依赖每次安装时自动选择新版本。

### 后端

- 使用 JDK 17、Maven 3.9.16 进行首次 `mvn -DskipTests package`。
- 构建成功，生成可执行 Spring Boot JAR；首次构建耗时约 7 分 15 秒。
- 当前依赖树很大，包含 Redis/Redisson、MinIO/OSS、WebSocket、Swagger、XXL-Job 等非核心能力；首次下载耗时明显，也会增加过渡版随包体积。

## 9. 第 1 步结论

现有 UI 框架和核心成绩页面具备较高复用价值，保留 80%～90% 视觉层是可行的。主要风险集中在动态权限路由、服务器依赖、历史数据模型不足和统计口径不符合需求。

安全改造路径是：先把菜单改为固定业务路由，同时保留布局组件；再从外围业务向内解除依赖；随后完成 SQLite 和本地文件迁移；核心成绩链路稳定后增加分析功能；最后接入 Tauri。直接删除 Spring Security、菜单表或 Spring Boot 都会造成大面积断链，不应作为第一刀。
