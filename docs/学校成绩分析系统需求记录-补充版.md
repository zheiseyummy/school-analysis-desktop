## 2. 系统定位

面向青海省西宁市学校的初高中成绩分析系统。

核心业务流程：

考试结束 → 导入成绩 → 校验与确认 → 分析 → 导出报告。

两大核心模块：

1. 学生成绩分析。
2. 教师任教成绩分析。

教师分析用于教学诊断，不用于教师考核评分。

### 2.1 使用范围

- 仅供用户个人使用。
- 仅分析本校数据，不涉及跨校联考排名。
- 同时支持初中和高中。
- 初中以各科考试成绩分析为主。
- 高中涉及选科组合、单科进退步、赋分等场景。

### 2.2 不包含的功能

- 考试安排、排考。
- 阅卷。
- 小题得分分析。
- 暂不设置多人账号和权限管理。
- 不设置登录密码或程序打开密码。

## 3. 交付与运行要求

- 最终交付 Windows EXE 可执行程序。
- 完全本地化，可离线运行。
- 学生信息及成绩数据不上网。
- 数据保存在本地。
- 以下操作均须在本机完成：
  - Excel 内容识别。
  - 数据导入与校验。
  - 成绩统计分析。
  - 赋分计算。
  - 报告生成与导出。
  - 数据备份与恢复。
- 不得将联网服务作为上述核心功能的运行前提。
- EXE 是安装程序还是免安装程序，尚未确定。

## 4. 学年、学期与考试归档

- 同一个程序保存多个学年、学期、年级的数据。
- 支持切换查看历史考试。
- 每次考试记录：
  - 考试名称。
  - 考试日期。
  - 所属学年。
  - 所属学期。
  - 所属年级。
- 上述信息用于归档及确定默认对照考试。
- 每次考试的满分、总分科目、计分方式等配置随考试保存。

## 5. 学生名单与学号

### 5.1 基础名单

- 每学期初导入学生名单。
- 后续成绩依据名单匹配。
- 每位学生使用唯一学号。
- 基础字段：
  - 学号。
  - 姓名。
  - 班级。
  - 年级。
- 支持后续自定义新增字段。
- 自定义字段的类型、校验和展示细节待确认。

### 5.2 学号规则

- 初中、高中分别管理学号。
- 不要求两个阶段沿用同一学号。
- 初中阶段学号保持不变。
- 高中阶段学号通常不变。
- 转班不改变学号。
- 高中确有学号变更时的处理方式待确认。

## 6. 高中选科与班级

### 6.1 选科模式

- 高中采用“3+1+2”模式。
- 不存在选科走班。
- 按固定班级管理，不单独设置走班教学班。

### 6.2 选科名单更新

- 基础学生名单导入后，可再次导入选科名单。
- 通过学号匹配学生。
- 根据新选科名单生成最新组合名单。
- 保留选科组合的历史版本。
- 历史考试默认按考试当时的选科组合分析。
- 必要时允许自主选择其他版本的组合名单。
- 不得因更新最新组合而直接覆盖历史组合。

## 7. 学生异动

- 记录转班、转入、转出的生效时间。
- 历史考试保留当时的学生归属信息。

### 7.1 转班

- 学号保持不变。
- 保存原班级、新班级及生效时间。
- 历史考试按当时班级分析。

### 7.2 转入

- 从实际转入时间开始纳入分析。
- 转入前的考试不按缺考处理。

### 7.3 转出

- 保存转出时间。
- 保留已有历史考试记录。
- 后续纳入统计的具体边界在实现前细化。

## 8. 教师任教关系

- 维护教师、任教学科、任教班级的对应关系。
- 支持：
  1. Excel 批量导入。
  2. 系统内手动设置。
- 任教关系变化时保存生效时间。
- 历史考试归属考试当时任教的教师。
- 同一教师教授多个班级时，支持：
  - 逐班查看分析。
  - 按学科汇总其任教班级的分析结果。
- 不同学科或不同年级的汇总边界待进一步细化。

## 9. 成绩导入

### 9.1 输入数据范围

- 包含各科成绩和总分。
- 不包含小题得分。
- 数据以学号匹配学生。

### 9.2 Excel 自动识别

- 自动识别：
  - 表头所在行。
  - 数据区域。
  - 各列含义。
- 根据表头及内容匹配学号、姓名、科目等字段。
- 不确定的匹配交由用户确认。
- 不仅依赖固定列名或固定表头位置。
- 用户将提供学校教师制作的 Excel 表，作为导入识别设计依据。
- 合并单元格、多工作表等具体处理规则，待样表到位后确认。

### 9.3 科目满分

- 导入时可设置每科满分。
- 支持因升年级或考试安排而改变满分。
- 满分配置随当次考试保存。
- 不用最新满分设置覆盖历史考试配置。

### 9.4 总分校验

- 比较导入表总分与系统按配置计算的总分。
- 不一致时展示差异并提醒。
- 用户核对后确认采用的结果。
- 不自动覆盖存在差异的总分。
- 涉及赋分及不同计入科目时，须明确校验所用口径。

## 10. 缺考处理

### 10.1 缺考识别

可能存在以下标记：

- 空白。
- “缺考”等文字。
- 特殊数字。
- 同一来源中出现多种形式。

要求：

- 导入时支持配置识别规则。
- 统一转换为明确的缺考状态。
- 正常的 0 分与缺考分开处理。
- 具体特殊数字及空白含义需依据样表确认。

### 10.2 计算规则

最终确认规则：

- 缺考不计入计算。
- 部分缺考学生仍参与已参加科目的统计与排名。
- 部分缺考学生不参与该次考试的总体总分排名。

已撤销的早期设想：

- “缺考可以选择计入或排除。”
- “缺考按 0 分计入。”

以上撤销内容不得作为默认功能实现。

## 11. 成绩修改与重新导入

### 11.1 修改方式

同时支持：

1. 系统内手动修改。
2. 重新导入文件批量更新。

### 11.2 同一次考试重新导入

- 按学号匹配。
- 更新文件中提供的学生及科目成绩。
- 保留文件未涉及的学生和科目。
- 写入前展示变更，由用户确认。
- 文件中的空白究竟表示缺考、清空或不更新，尚需单独明确，不能静默推断。

### 11.3 修改记录

- 保留修改前后的数值。
- 保留修改记录。
- 支持撤销误操作。
- 批量撤销及撤销后关联统计的处理细节待设计。

## 12. 总分配置

### 12.1 初中

- 每次考试可自由选择计入总分的科目。
- 配置随考试保存。

### 12.2 高中

- 每次考试可自由选择计入总分的科目。
- 可逐科选择使用原始分或赋分。
- 配置随考试保存。
- 原始分保留，赋分单独保存。
- 具体可赋分科目及规则在开发前核实。

## 13. 高中赋分

### 13.1 导入后的选择

支持：

1. 使用成绩表中已有的赋分。
2. 由系统根据原始分计算赋分。
3. 不启用赋分，仅按原始分分析。

### 13.2 赋分规则

- 默认采用经核实的青海省适用规则。
- 支持自定义赋分规则。
- 政策规则、适用年级及具体计算细节尚未核实，不视为已经确定。

### 13.3 关键待定事项

赋分计算的学生群体尚未确定。

此前提出过“本次考试中本校同年级、选考该科且实际参加考试的学生”，但用户明确要求待定，因此：

- 不把该群体当成已确认默认值。
- 等用户明确计算范围后再开发相关逻辑。
- 学生名单用于身份、选科及归属管理，不自动等同于赋分计算群体。

## 14. 排名规则

### 14.1 排名范围

同时支持：

- 班级范围。
- 本校同年级整体范围。

不涉及跨校排名。

### 14.2 高中总分排名

支持切换：

1. 按选科组合排名。
2. 按物理类、历史类分别排名。

### 14.3 同分处理

同分并列，并跳过后续名次。

示例：

1、2、2、4。

### 14.4 单科与总分排名差距

- 比较单科排名与总分排名时，使用同一学生群体。
- 不直接混用不同群体的排名计算差距。
- 无有效总分排名的学生如何展示差距，待实现前细化。

## 15. 学生成绩分析

第一版已确认指标：

1. 总分变化。
2. 单科分数变化。
3. 总分排名、单科排名变化。
4. 单科排名与总分排名之间的差距变化。

要求：

- 支持班级和本校同年级整体范围。
- 高中结合选科组合、物理类和历史类口径。
- 其他指标用户后续想到再补充。

### 15.1 对照考试

- 默认对比上一次考试。
- 允许用户自行选择其他考试。
- “上一次”的精确筛选规则待实现前明确，例如同年级、同科目和日期相同的情况。

### 15.2 比较口径变化

如果考试之间的计入科目或满分不同：

- 展示口径差异。
- 提醒用户。
- 用户确认后再比较。
- 支持选择共同科目比较。
- 不把不同口径的分数变化静默解释为实际进退步。

## 16. 教师教学诊断

### 16.1 用途

- 用于教学诊断。
- 帮助教师了解任教班级表现、薄弱环节和变化。
- 暂不设置教师考核评分。

### 16.2 第一版指标

1. 均分。
2. 及格率。
3. 优秀率。
4. 分数段分布。
5. 与年级平均水平的差距。
6. 历次考试进退步。

### 16.3 展示范围

- 任教班级分别分析。
- 同一教师同学科多个任教班级汇总分析。
- 具体统计分母、比较群体和汇总方式须在实现前明确。

## 17. 及格线、优秀线与分数段

### 17.1 默认标准

- 及格线：满分的 60%。
- 优秀线：满分的 80%。
- 每次考试允许修改。

### 17.2 分数段

- 默认按满分比例划分。
- 支持自定义调整。
- 具体默认区间、边界包含方式尚未确定。
- 所用标准应与考试关联保存，避免影响历史结果。

## 18. 报告与导出

### 18.1 格式

同时支持：

- Excel。
- PDF。

### 18.2 报告层级

- 学生分析报告。
- 班级分析报告。
- 年级分析报告。
- 教师分析报告。

### 18.3 批量导出

- 支持批量生成独立报告。
- 包括全年级学生、各班级和各教师报告。
- 文件命名、目录结构、打包方式待设计。

### 18.4 模板

- 用户将提供具体报告模板。
- 收到模板后再确认版式、内容和调整范围。
- 当前不预先定稿。
- 不直接将历史样式或演示页面视为最终需求。

## 19. 本地备份与恢复

- 支持手动备份。

## 26. 单机本地化桌面版改造基线（2026-09-23）

用户明确要求将现有项目分阶段改造成仅供个人使用的 Windows 本地成绩分析桌面软件。以下要求作为后续实施基线：

- 最终完全离线、单用户、免安装或绿色便携、双击 EXE 运行，支持 Windows 10/11。
- 最终用户不单独安装 MySQL、Redis、MinIO、JDK、Node.js、Tomcat或其他服务器环境。
- 优先采用 Vue3 + Tauri + SQLite，除非验证存在 Tauri 无法解决的兼容问题；不优先使用 Electron。
- 尽量保留现有 Vue3 + Element Plus UI，包括布局、主题、图标、表格、表单、弹窗、卡片和 ECharts 风格，预计保留视觉层 80%～90%。
- 不保留多人账号、RBAC、数据权限、JWT、Redis Session和在线用户体系；第一选择为启动后直接进入主页。
- 核心功能包含基础资料、考试、成绩导入/修改/查询/删除/导出，以及首页、年级、班级、学科、学生、进退步和临界生分析。
- 学生个人分析为重点：历史成绩、班级/年级排名、单科趋势、优势/薄弱/偏科、进退步及学科雷达图。
- 复杂学情档案改为学生备注、学习状态、特殊情况和跟进记录。
- MySQL迁移为本地 `data/school.db`；MinIO改本地目录；建议使用 `data/`、`files/`、`backup/`、`export/`。
- SQLite需支持自动备份、立即备份和恢复；默认建议保留最近30个备份，恢复前必须确认。
- 所有学生和成绩数据仅存本机，不调用互联网API、不上传数据、不使用云数据库或远程日志。
- 不一次性重写或删除全部 Spring Boot；先解除依赖、精简业务、切换 SQLite并保持可运行，再评估迁移为 Tauri Rust Command。
- 每阶段遵循依赖分析、修改、编译、数据库/路由/菜单检查和核心业务验证，不留下无效菜单、404、空页面、失效按钮或无效API。
- 实施严格按用户给出的12步顺序推进：结构分析、模块分类、菜单路由、外围业务删除、登录精简、Redis、MinIO、本地SQLite、核心验证、新分析能力、备份、Tauri打包。

第1步和第2步的详细结论已分别记录在《单机桌面版改造-第1步项目结构与依赖分析》和《单机桌面版改造-第2步模块处置清单》。
