# 成绩分析系统详细使用说明

版本：Windows `1.1 beta` 便携桌面版
适用对象：在一台 Windows 电脑上独立管理学校成绩的个人用户
说明日期：2026-10-09

> 这是试用版说明。程序已在开发电脑完成窗口启动、后端接口和隔离数据目录冒烟测试；学校真实成绩表的全流程验收，以及其他 Windows 电脑验收仍需继续。正式使用前请先备份，并用少量脱敏数据核对导入结果。

## 1. 这个程序能做什么

系统用于本机维护年级、班级、学生、教师和学科信息，记录考试及成绩，并查看年级、班级、学科和学生个人分析。还包含初中综合素质评价、高中选科信息、学生报告导出和本地备份恢复。

程序面向单人使用：没有登录、账号权限或多人同时编辑功能，不需要部署远程服务器。桌面窗口内部会启动一个只监听本机的服务，业务数据库和文件保存在当前 Windows 用户的电脑上。

## 2. 安装和启动

1. 获取 `成绩分析系统_1.1(beta)_Windows_x64.zip`，将整个压缩包解压到本机有读写权限的目录。
2. 不要只复制 `成绩分析系统.exe`；它需要同目录的 `backend.jar` 和 `runtime` 文件夹。
3. 双击 `成绩分析系统.exe`。程序会在单独的桌面窗口打开，不需要手动打开浏览器。
4. 关闭程序窗口即可退出本次运行的桌面程序和本地服务。

通常不需要另外安装 Node.js、Java 或 Maven。Windows 如果提示缺少 WebView2 Runtime，请安装 Microsoft Edge WebView2 Evergreen Runtime 后重试。第一次运行需要等待本地数据库初始化；如果 Windows 防火墙弹出网络提示，程序只需本机回环通信，不应配置为供局域网访问。

发行文件位置（源码工作区）：

- 便携包：`outputs/成绩分析系统_1.1(beta)_Windows_x64.zip`
- 解压后启动：`outputs/成绩分析系统_1.1(beta)_Windows_x64/成绩分析系统.exe`

## 3. 数据保存在哪里

桌面版将数据库、上传文件、备份、导出和日志放在：

```text
%LOCALAPPDATA%\成绩分析系统
```

把程序 ZIP 解压到另一目录或升级程序，不会自动把旧电脑的数据带过去；程序文件夹与数据目录是分开的。跨电脑迁移请在旧电脑中创建备份，再通过新电脑的备份恢复功能导入。不要把真实学生数据库、成绩表或个人报告上传到 GitHub。

## 4. 推荐的日常操作顺序

### 第一步：维护基础信息

进入“基础信息”，按顺序维护年级、班级、学生、教师资料和学科。

- **年级管理**：先建立当前需要管理的年级，并核对学段和学年信息。
- **班级管理**：将班级归属到正确年级，维护班级编号和班主任。页面不单独要求填写班级名称，系统会按编号在内部生成名称。
- **学生管理**：填写学号、姓名等当前页面要求的信息，并设置学生对应的年级、班级年度关系。列表支持先选年级、再选班级筛选。
- **教师资料**：维护教师姓名；在教师新增或编辑窗口中按“年级→班级→学科”添加任教关系。教师列表会显示所带班级和任教学科，点击教师姓名可修改资料。
- **学科管理**：核对学校实际使用的科目名称，避免成绩表中的科目与系统科目不一致。
- **高中选科与赋分**：可维护高中 `3+1+2` 选科组合信息。赋分计算规则目前暂停，学校政策未确认前不要把配置框架当成正式赋分结果。

页面已按单人业务精简：一些不需要的头像、年龄、状态、工号等展示字段已隐藏；隐藏展示并不意味着底层学生、班级和教师关联关系被删除。

### 第二步：建立考试并配置科目

进入“成绩管理→考试管理”：

1. 创建考试，填写考试名称、学年、学期和考试日期等页面要求的信息。
2. 用年级、班级筛选查找考试。列表显示“考试人数”。
3. 在考试操作中设置本次考试的适用对象，并配置本场实际考试科目。
4. 为每个科目检查满分，并确认是否计入总分。该设置会影响总分、排名、分析和报告。

考试类型、考试编码、考试对象摘要和状态字段不在当前管理页面展示；内部仍保留必要兼容字段。注意：考试对象配置入口仍然存在，它用于确定本场考试涉及的年级或班级。

### 第三步：导入成绩

进入“成绩管理→成绩录入”：

1. 选择对应考试和筛选条件。
2. 点击文件选择按钮，选择 `.xlsx` 或 `.xls` 文件。当前只支持选择文件，不支持拖拽上传。
3. 按页面提示检查工作表、列识别、学生匹配、科目和成绩校验结果。
4. 先看预览和差异，再确认提交。不要仅凭“上传成功”就认为所有行都正确。
5. 检查导入批次、异常行和学生匹配情况；必要时按页面功能重新导入或撤销批次。

成绩状态需要区分：

- **正常分数 0**：是真实的零分，仍是有效成绩，会按配置参与统计。
- **缺考**：学生本次未参加考试，不应录成 0 分。
- **未选科**：该学生本次不适用该科目，不应录成 0 分。
- **空白或缺失**：先确认是录入遗漏、转入学生没有历史成绩，还是学校表格本身为空，再决定如何处理。

表头名称变化和合并单元格不保证都能自动识别。系统会尝试识别常见列名，但每次考试都应检查导入预览；如果列错位、合并表头无法识别或学生对应不上，请先停止确认，提供脱敏样表再核对。不要为了让导入通过而猜测学生或分数。

### 第四步：查看分析和导出个人报告

进入“学情分析”，按实际业务页面选择考试、年级、班级、学生或学科查看分析。系统提供年级、班级、学生、学科分析，以及历次考试比较、进退步、临界生、偏科等已实现的第一版功能。

学生个人成绩报告支持：

- 单个学生单独导出 Excel 或 PDF。
- 按班级批量导出，每位学生仍生成独立文件，并打包成 ZIP。
- Excel 内含“综合分析、趋势变化、学科诊断、家长沟通”四个工作表。
- 每位学生的 PDF 为同一文件中的四页 A4 内容。

导出前先确认学生、考试和班级筛选条件。报告中的学生必须与所选学生/考试逐一对应；发现姓名或成绩不一致时，先检查学号、考试对象和原始成绩，不要直接分发报告。

### 第五步：维护初中综合素质评价

进入“综合素质评价”：

1. 选择班级，导入学校格式的综合素质 Excel 工作簿。
2. 工作簿需提供六个学期的数据表，并包含可用于匹配的学号/考号、姓名和五个维度数据。以页面导入提示和预览为准。
3. 系统优先按学号匹配学生。导入后检查学生总数、学期记录数和未匹配情况。
4. 对缺失学期逐条确认：确认是缺失，还是学生中途转入、之前没有本校成绩。
5. 生成最终结果后，检查分值、比例和等级建议；比例按设置计算，教师需要最终核对并确认等级。
6. 存在已确认缺失学期的学生，最终维度等级显示 `N/A`，不参与 A/B/C 比例和排名。
7. 确认无误后再锁定或导出最终表。

最终人数依据最后一个学期工作表的名单确定。日常界面不需要操作“基准”设置；导入文件时要确认该工作表就是学校认可的最终名单。

### 第六步：备份和恢复

进入“数据工具→数据备份”：

- **备份**：建议在导入新考试、批量修改或升级程序前执行，并确认备份列表出现新文件。
- **恢复**：选择系统生成的备份，确认后按页面提示完成恢复；恢复后重新打开相关页面核对年级、学生和成绩。
- **保留数量**：系统管理最近 30 份自动/手动备份。
- **跨电脑迁移**：把备份文件通过学校批准的安全方式传到新电脑，在新电脑中执行恢复。不要通过公开网盘或 GitHub 传送真实学生信息。

## 5. 常见问题

### 双击后窗口没有打开或提示缺少组件

确认 ZIP 已完整解压、文件夹可写，并且没有只复制 EXE。若提示 WebView2 缺失，安装 Microsoft Edge WebView2 Evergreen Runtime 后重试。

### 窗口空白或提示“本地服务请求失败”

关闭程序后重新启动；检查本机 `8989` 端口是否已被其他应用占用。不要同时打开多个旧版本。若仍失败，记录提示截图并保留 `logs` 文件夹后再联系开发人员。

### 导入后人数不对或出现未匹配

先不要确认提交。核对考试对象、工作表、学号列、重复学生、转入学生和表头映射；空白成绩也不要直接改成 0。

### 新电脑上没有旧数据

这是正常的：程序数据存放在每台电脑各自的 `%LOCALAPPDATA%`。从旧电脑备份，在新电脑恢复；单独复制程序不会同步数据。

### 是否可以多人同时使用

当前版本只按一台 Windows 电脑、一个本地用户设计，不支持多人并发编辑、账号权限、远程访问或服务器部署。

## 6. 使用前的安全检查清单

- [ ] 压缩包完整解压，没有只复制 EXE。
- [ ] 基础信息和年级、班级、学生关系正确。
- [ ] 考试的学期、适用对象、科目满分和计总分配置正确。
- [ ] 导入先预览，学号匹配和异常行已核对。
- [ ] 缺考、未选科、空白、真实 0 分没有混淆。
- [ ] 导出前确认学生、班级和考试；批量报告抽查几名学生。
- [ ] 重要操作前有可读取的最新备份。

## 7. 当前版本边界

`1.1 beta` 是便携试用版，不是正式安装程序。学校真实成绩表、复杂合并表头、各校状态词、正式报告样式、高中赋分政策和其他 Windows 电脑离线启动仍需逐项验收。发现业务规则不确定时，先记录问题并向学校确认，不要让系统自动猜测。
